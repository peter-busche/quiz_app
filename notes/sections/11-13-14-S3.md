# 🅰️ Part A — Section 11: Amazon S3 Introduction

## A1. What is S3 & Use Cases — slides [214](../../AWS_Certified_Developer_Slides_v45.pdf#page=214)–215

- One of the **main building blocks** of AWS — "**infinitely scaling**" storage
- Backbone for many websites; integrated with many AWS services
- Use cases: backup & storage, **disaster recovery**, **archive**, hybrid cloud storage, application & **media hosting**, **data lakes / big data analytics**, software delivery, **static websites**

**Your S11 Q2:** "standards-based **REST** interface, stores objects by **keys**" → **Amazon S3**

---

## A2. Buckets — slide [216](../../AWS_Certified_Developer_Slides_v45.pdf#page=216)

- **Buckets** (≈ directories) hold **objects** (files)
- ⭐ **Buckets are defined at the region level** — S3 *looks* global, but buckets live in a region
- Naming:
  - **Shared global namespace** — globally unique name (all regions, all accounts)
  - **Account regional namespace** — allows reusing the same name across regions
- Naming constraints: **no uppercase, no underscore**, **not an IP**, must **start with a lowercase letter or number**, must not start with `xn--`, must not end with `-s3alias`

---

## A3. Objects — slides [217](../../AWS_Certified_Developer_Slides_v45.pdf#page=217)–218

- Each object has a **key** = the **full path**: `s3://my-bucket/my_folder1/another_folder/my_file.txt`
- **Key = prefix + object name** (`my_folder1/another_folder/` + `my_file.txt`)
- ⚠️ **There are no real directories** — just keys containing `/` (the UI pretends)

| Object part | Detail |
|---|---|
| **Value** (body) | Max object size **50 TB** (per slide) |
| ⭐ **Upload > 5 GB** | **Must use multipart upload** |
| **Metadata** | Text key/value pairs (system or user) |
| **Tags** | Unicode key/value, **up to 10** — useful for **security / lifecycle** |
| **Version ID** | If versioning is enabled |

---

## A4. Security Basics & Bucket Policies — slides [219](../../AWS_Certified_Developer_Slides_v45.pdf#page=219)–225

### Ways to control access
| Type | Mechanism | Notes |
|---|---|---|
| **User-based** | **IAM policies** | Which API calls a specific IAM user/role can make |
| **Resource-based** | **Bucket policies** | Bucket-wide rules — ⭐ **allows cross-account** |
| | **Object ACL** | Finer grain (can be disabled) |
| | **Bucket ACL** | Less common (can be disabled) |
| **Encryption** | Keys | See Part C |

### ⭐ The access rule
> An IAM principal can access an S3 object **if** the **IAM permissions ALLOW it OR the resource policy ALLOWS it**, **AND** there is **no explicit DENY**.

### Bucket policy structure (JSON)
`Resource` (buckets & objects) · `Effect` (Allow/Deny) · `Action` (APIs) · `Principal` (account/user)

**Use a bucket policy to:**
- Grant **public access** to the bucket
- ⭐ **Force objects to be encrypted** at upload
- Grant access to **another account** (cross-account)

### Which mechanism for which scenario
| Scenario | Use | Slide |
|---|---|---|
| Anonymous public website visitor | **Bucket policy** allowing public access | 221 |
| IAM user in your account | **IAM policy** | 222 |
| ⭐ **EC2 instance** | **IAM role** (instance role) | 223 |
| User in **another AWS account** | **Bucket policy** allowing cross-account | 224 |

### Block Public Access
- Created to **prevent company data leaks**
- Bucket should never be public → **leave these on**
- Can be set at the **account level**

**Your S14 Q6:** EC2 can't reach the bucket → check **(1) the EC2 instance's IAM role** and **(2) the bucket policy**.

## A5. Static Website Hosting — slide [226](../../AWS_Certified_Developer_Slides_v45.pdf#page=226)

- S3 can host **static websites** on the internet
- URL: `http://bucket-name.s3-website-aws-region.amazonaws.com` **or** `http://bucket-name.s3-website.aws-region.amazonaws.com`
- ⭐ **403 Forbidden** → make sure the **bucket policy allows public reads** (and Block Public Access is off)
- ⚠️ The website endpoint is **HTTP only** → for HTTPS put **CloudFront** in front (see your CloudFront notes)

**Your S11 Q3:** serverless website with HTML, images, video, JS → **S3 + CloudFront**

## A6. Versioning — slide [227](../../AWS_Certified_Developer_Slides_v45.pdf#page=227)

- Enabled at the **bucket level**
- Same key overwrite → new **version** (1, 2, 3…)
- ⭐ Best practice: protects against **unintended deletes** (restore a version) and allows **easy rollback**
- Files uploaded **before** enabling versioning have version **`null`**
- ⚠️ **Suspending versioning does not delete previous versions**

---

## A7. Replication (CRR & SRR) — slides [228](../../AWS_Certified_Developer_Slides_v45.pdf#page=228)–229

- ⭐ **Versioning must be enabled on BOTH source and destination**
- Buckets can be in **different AWS accounts**
- Copying is **asynchronous**
- Needs proper **IAM permissions** for S3

| | **CRR (Cross-Region)** | **SRR (Same-Region)** |
|---|---|---|
| Use cases | **Compliance**, lower-latency access, replication **across accounts** | **Log aggregation**, live replication between **prod and test** accounts |

### Replication notes
- ⚠️ **Only new objects** are replicated after enabling → existing/failed objects need **S3 Batch Replication**
- **Delete markers** can optionally be replicated
- ⚠️ **Deletions with a version ID are NOT replicated** (prevents malicious deletes)
- ⚠️ **No chaining:** bucket 1 → bucket 2 → bucket 3 does **not** copy bucket 1's objects to bucket 3

**Your S11 Q1:** infrequently accessed files, compliance requires copies **across regions**, cost-effective → **S3 with Cross-Region Replication**

## A8. Storage Classes, Durability & Availability — slides [230](../../AWS_Certified_Developer_Slides_v45.pdf#page=230)–237

### Durability vs availability
| | Durability | Availability |
|---|---|---|
| Means | How likely you are to **lose** an object | How readily the service **responds** |
| Value | ⭐ **11 9's (99.999999999%)** — **same for all classes** | **Varies by class** (Standard = 99.99% ≈ 53 min/year down) |

### The classes
| Class | Availability | AZs | Min duration | Retrieval | Use for |
|---|---|---|---|---|---|
| **Standard** | 99.99% | ≥ 3 | None | Instant, no fee | **Frequently accessed** data, analytics, gaming, content distribution |
| **Intelligent-Tiering** | 99.9% | ≥ 3 | None | Instant, **no retrieval fee** (monitoring fee) | **Unknown / changing** access patterns |
| **Standard-IA** | 99.9% | ≥ 3 | **30 days** | Instant, per-GB fee | **Infrequent but fast** access — DR, backups |
| **One Zone-IA** | 99.5% | ⚠️ **1** | **30 days** | Instant, per-GB fee | **Data you can recreate**, secondary backup copies |
| **Glacier Instant Retrieval** | 99.9% | ≥ 3 | **90 days** | **Milliseconds** | Accessed **once a quarter** |
| **Glacier Flexible Retrieval** | 99.99% | ≥ 3 | **90 days** | Expedited **1–5 min**, Standard **3–5 h**, Bulk **5–12 h (free)** | Archive |
| **Glacier Deep Archive** | 99.99% | ≥ 3 | **180 days** | Standard **12 h**, Bulk **48 h** | **Long-term** archive, cheapest |

### Intelligent-Tiering tiers
| Tier | When |
|---|---|
| Frequent Access | Default |
| Infrequent Access | Not accessed **30 days** |
| Archive Instant Access | Not accessed **90 days** |
| Archive Access (optional) | 90 – 700+ days |
| Deep Archive Access (optional) | 180 – 700+ days |

### Price ladder (us-east-1, per GB/month — slide 237)
`Standard $0.023 → Standard-IA $0.0125 → One Zone-IA $0.01 → Glacier Instant $0.004 → Glacier Flexible $0.0036 → Deep Archive $0.00099`

> Memory trick: **the longer you promise to keep it and the longer you'll wait to get it back, the cheaper it is.**

# 🅱️ Part B — Section 13: Advanced Amazon S3

## B1. Moving Between Storage Classes & Lifecycle Rules — slides [249](../../AWS_Certified_Developer_Slides_v45.pdf#page=249)–252

- Infrequently accessed → **Standard-IA**; archive → **Glacier / Deep Archive**
- ⭐ Automate with **Lifecycle Rules**

| Action type | Example |
|---|---|
| **Transition actions** | Move to Standard-IA **60 days** after creation; to Glacier after **6 months** |
| **Expiration actions** | Delete access logs after **365 days**; ⭐ delete **old versions**; ⭐ delete **incomplete multipart uploads** |

- Rules can target a **prefix** (`s3://mybucket/mp3/*`) or **object tags** (`Department: Finance`)

### Scenario 1 — thumbnails (slide 251)
> Source images: instant access for 60 days, then up to 6 h wait. Thumbnails: recreatable, keep 60 days.
- **Source images → Standard**, lifecycle **transition to Glacier after 60 days**
- **Thumbnails → One Zone-IA** (recreatable), lifecycle **expire after 60 days**

### Scenario 2 — recover deletes (slide 252)
> Recover deleted objects **immediately for 30 days**, then **within 48 h for up to 365 days**.
- **Enable versioning** (deletes become **delete markers** → recoverable)
- Transition **noncurrent versions → Standard-IA**
- Then transition **noncurrent versions → Glacier Deep Archive**

## B3. S3 Event Notifications — slides [254](../../AWS_Certified_Developer_Slides_v45.pdf#page=254)–256

- Events: `s3:ObjectCreated`, `s3:ObjectRemoved`, `s3:ObjectRestore`, `s3:Replication`…
- **Object name filtering** (`*.jpg`); as many events as you want
- Use case: **generate thumbnails** on upload
- Delivered in **seconds**, sometimes **a minute or longer**
- Destinations: **SNS, SQS, Lambda**

### Permissions — ⭐ resource policies on the destination
| Destination | Needs |
|---|---|
| SNS | **SNS resource (access) policy** |
| SQS | **SQS resource (access) policy** |
| Lambda | **Lambda resource policy** |

> ⚠️ Not an IAM role on S3 — the **destination's resource policy** must allow S3.

### With Amazon EventBridge
- **All events** go to EventBridge → rules → **18+ AWS services** as destinations (Step Functions, Kinesis Streams/Firehose…)
- **Advanced filtering** with JSON rules (metadata, object size, name…)
- **Archive, replay events, reliable delivery**

## B4. Performance — slides [257](../../AWS_Certified_Developer_Slides_v45.pdf#page=257)–259

### Baseline
- Auto-scales; latency **100–200 ms**
- ⭐ **3,500 PUT/COPY/POST/DELETE** and **5,500 GET/HEAD** requests **per second per prefix**
- **No limit on the number of prefixes**
- Prefix = path between bucket and object name: `bucket/folder1/sub1/file` → `/folder1/sub1/`
- 4 prefixes × 5,500 = **22,000 GET/s**

**Your S13 Q1:** **55,000 reads/s** → 55,000 ÷ 5,500 = **at least 10 prefixes**

### Upload & download speed-ups
| Feature | What it does | When |
|---|---|---|
| ⭐ **Multipart upload** | Split into parts, upload **in parallel** | **Recommended > 100 MB**, **must > 5 GB** |
| ⭐ **S3 Transfer Acceleration** | Upload to a nearby **edge location**, then over the **private AWS network** to the bucket's region | **Far-away uploaders** (global offices) — compatible with multipart |
| **Byte-Range Fetches** | **Parallel GETs** of specific byte ranges | Speed up **downloads**, better resilience, or fetch **only part** (e.g. a file header) |

**Your S13 Q2 & Q4:** global offices, slow uploads → **S3 Transfer Acceleration**

# 🅲 Part C — Section 14: Amazon S3 Security

## C1. Object Encryption — the 4 methods — slides [262](../../AWS_Certified_Developer_Slides_v45.pdf#page=262)–267

| Method | Who manages the key | Header | Key facts |
|---|---|---|---|
| **SSE-S3** | **AWS / S3** (owned & managed) | `"x-amz-server-side-encryption": "AES256"` | ⭐ **Enabled by default** for new buckets & objects; AES-256 |
| **SSE-KMS** | **AWS KMS** | `"x-amz-server-side-encryption": "aws:kms"` | ⭐ **User control + audit key usage in CloudTrail** |
| **SSE-C** | **Customer, outside AWS** | Key sent in headers **on every request** | ⚠️ **S3 does NOT store the key**; ⚠️ **HTTPS required** |
| **Client-side** | **Customer** (encrypts before upload) | — | Client encrypts/decrypts itself (S3 Client-Side Encryption Library) |

### ⚠️ SSE-KMS limitation (slide 265)
- **Upload → `GenerateDataKey`**, **download → `Decrypt`** KMS API calls
- These **count toward the KMS quota** (5,500 / 10,000 / 30,000 req/s by region)
- Throttled? → request a **quota increase** (Service Quotas console) — also see **S3 Bucket Key** in your Section 30 notes

### Which one?
| Question says… | Answer |
|---|---|
| "encrypted at rest", nothing more | **SSE-S3** (default) |
| "audit key usage", "control keys", "rotation" | **SSE-KMS** |
| "company manages keys **outside AWS**", "S3 must not store the key" | **SSE-C** |
| "encrypt **before** uploading", "S3 never sees plaintext" | **Client-side** |

---

## C2. Encryption in Transit & Forcing Encryption — slides [268](../../AWS_Certified_Developer_Slides_v45.pdf#page=268)–270

- S3 has an **HTTP** (unencrypted) and an **HTTPS** (encrypted in flight) endpoint
- **HTTPS recommended**; ⚠️ **mandatory for SSE-C**; most clients use HTTPS by default

### Force encryption **in transit**
Bucket policy that **denies** requests where **`aws:SecureTransport` = false**

**Your S14 Q5 & Q7:** "data must be encrypted **in transit** to S3" → **bucket policy with `aws:SecureTransport`**

### Force encryption **at rest**
- **SSE-S3 is applied automatically** to new objects (default encryption)
- Optionally **force** a specific encryption with a **bucket policy that denies PutObject without encryption headers** (e.g. SSE-KMS or SSE-C)
- ⚠️ **Bucket policies are evaluated BEFORE default encryption**

**Your S14 Q1:** "all data written must be encrypted" → **bucket policy denying PutObject without `x-amz-server-side-encryption`**

## C3. CORS — slides [271](../../AWS_Certified_Developer_Slides_v45.pdf#page=271)–273

- **Origin = scheme + host + port** (`https://www.example.com` → port 443 implied)
- **Browser-based** mechanism to allow requests to **other origins**
  - Same origin: `http://example.com/app1` & `http://example.com/app2`
  - Different origins: `http://www.example.com` & `http://other.example.com`
- Browser sends a **preflight `OPTIONS`** request → other origin replies with **CORS headers** (`Access-Control-Allow-Origin`, `Access-Control-Allow-Methods`)

### S3 + CORS ("a popular exam question")
```
Browser loads index.html from  my-bucket-html  ──▶ page requests coffee.jpg from  my-bucket-assets
                                                    ⭐ CORS must be enabled on my-bucket-ASSETS
                                                    Access-Control-Allow-Origin: http://my-bucket-html...
```
- Allow a **specific origin** or **`*`** (all origins)
- ⚠️ CORS is configured on the bucket **being requested** (the **other** bucket), not the one serving the page

**Your S14 Q3:** site `dctlabs.com` loads images from `dctlabsimages` bucket, images don't display → **CORS not enabled on the `dctlabsimages` bucket**

## C5. S3 Access Logs — slides [275](../../AWS_Certified_Developer_Slides_v45.pdf#page=275)–276

## C6. Pre-Signed URLs — slide [277](../../AWS_Certified_Developer_Slides_v45.pdf#page=277)

- Generate with the **S3 Console, AWS CLI, or SDK**
- ⭐ Users with the URL **inherit the permissions of the user who generated it** (GET / PUT)

| Generated with | Expiration |
|---|---|
| **S3 Console** | 1 min – **720 min (12 h)** |
| **AWS CLI** | `--expires-in` seconds — default **3600 s**, max **604,800 s (~168 h / 7 days)** |

**Examples:**
- Only **logged-in users** download a **premium video**
- An **ever-changing list of users** download files (URLs generated dynamically)
- **Temporarily let a user upload** to a precise location in a private bucket (PUT)

### Your questions
| Question | Answer |
|---|---|
| **S13 Q3** — premium content only for **paid subscribers**, bucket private | **Pre-signed URL** when a subscriber requests a download |
| **S14 Q2** — staff securely share files from a **private** bucket | **S3 pre-signed URLs** |
| **S14 Q4** — other sites **hotlink** your photos | **Remove public read**, use **signed URLs with expiry** |
| **S14 Q9** — SNS emails must link to objects in a **secured** bucket, SIMPLEST | **SDK `GeneratePresignedUrlRequest`** → pre-signed URL |
| **S14 Q8** — premium customers get updates through **CloudFront** | **CloudFront signed URL** + **OAI/OAC** restricting the bucket to CloudFront |

> ⚠️ **S3 pre-signed URL** (S3 only, acts as the signer's IAM identity) **≠ CloudFront signed URL** (via CloudFront, filters by IP/path/date, uses caching). "Through CloudFront" → **CloudFront signed URL**.

## C7. S3 Access Points — slides [278](../../AWS_Certified_Developer_Slides_v45.pdf#page=278)–279

- ⭐ **Simplify security management at scale** — one bucket, many access points
- Example: **Finance** access point (R/W `/finance`), **Sales** (R/W `/sales`), **Analytics** (read entire bucket)
- Each access point has its **own DNS name** (**Internet origin** or **VPC origin**) and its **own access point policy** (like a bucket policy)

### VPC origin
- Access point reachable **only from within a VPC**
- Must create a **VPC Endpoint** (Gateway or Interface)
- Three policies must allow access: **VPC endpoint policy → access point policy → bucket policy**

## C8. S3 Object Lambda — slide [280](../../AWS_Certified_Developer_Slides_v45.pdf#page=280)

- Use **Lambda functions to change an object before it's returned** to the caller

## 🚨 Top Exam Traps

1. **Access = (IAM OR bucket policy allows) AND no explicit deny.**
2. **Cross-account → bucket policy**; **EC2 → IAM role**.
3. **Buckets are regional**; keys are full paths — **no real folders**.
4. **> 5 GB must use multipart**; Transfer Acceleration is for **distance**, not file size.
5. **5,500 GET/s per prefix** → divide the required rate by 5,500 to get the prefix count.
6. **Replication needs versioning on both buckets**, only replicates **new** objects, and **doesn't chain**.
7. **Deletes with a version ID are not replicated.**
8. **Suspending versioning keeps old versions**; files from before versioning have version **`null`**.
9. **One Zone-IA = 1 AZ** → only for **recreatable** data.
10. **Storage Class Analysis only recommends Standard → Standard-IA.**
11. **Event notification permissions = the destination's resource policy** (SNS/SQS/Lambda).
12. **You can't search metadata/tags** → index in **DynamoDB**.
13. **SSE-C requires HTTPS** and S3 **doesn't store the key**; **SSE-KMS counts against KMS quotas**.
14. **`aws:SecureTransport` = in transit**; **`x-amz-server-side-encryption` = at rest**. Bucket policies are evaluated **before** default encryption.
15. **CORS goes on the bucket being requested**, not the bucket serving the page.
16. **MFA Delete needs versioning and the root account.**
17. **Access logs → a different bucket in the same region** (never the same bucket).
18. **Pre-signed URLs inherit the generator's permissions**; console max 12 h, CLI max 7 days.
19. **Website endpoint is HTTP only** → HTTPS needs **CloudFront**.
